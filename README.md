# دنتالفای (Dentalfy) — پلتفرم آموزش تخصصی دندانپزشکی

پلتفرم تحت وب برای انتشار، دسته‌بندی و مطالعهٔ منابع آموزشی دروس دندانپزشکی، همراه با پنل اختصاصی مدیریت، ویرایشگر بلوکی محتوا و بک‌اند آمادهٔ اتصال به PostgreSQL.

این پروژه را با نام برند شخصی **RMO** طراحی و پیاده‌سازی کرده‌ام تا دانشجویان و مدرسان دندانپزشکی بتوانند جزوات، ویدیوها، فایل‌های PDF و مطالب بالینی را در یک محیط ساختاریافته، سریع و کاملاً راست‌به‌چپ (RTL) منتشر و مطالعه کنند.

## درباره پروژه

هدف من از ساخت **دنتالفای** ایجاد یک مرجع آموزشی منظم بود که بدون نیاز به ابزارهای سنگین و پیچیده، هم روی حالت محلی مرورگر (برای تست سریع یا استفاده سبک) کار کند و هم امکان اتصال به یک سرور واقعی با دیتابیس رابطه‌ای و احراز هویت امن را داشته باشد.

طراحی ظاهری پروژه با تمرکز بر خوانایی متون فارسی (فونت Vazirmatn)، پالت رنگی کلینیکی، پشتیبانی از حالت تیره و روشن (`dark` / `light`) و چیدمان واکنش‌گرا برای موبایل و دسکتاپ انجام شده است.

## امکانات و بخش‌ها

### ۱. بخش عمومی سایت (`index.html`)
- **بخش معرفی (Hero):** نمایش عنوان، شعار پلتفرم و آمار کلی دروس، مطالب و اعضای فعال (قابل شخصی‌سازی از پنل مدیریت).
- **دروس تخصصی (`#courses`):** دسته‌بندی دروس اصلی شامل آناتومی دهان و دندان، پاتولوژی دهان، پروتز دندانی، اندودنتیکس، پریودنتولوژی و ارتودنسی.
- **بخش مطالب آموزشی (`#posts`):** نمایش کارت‌های پست همراه با جستجوی لحظه‌ای و فیلتر بر اساس درس.
- **کتابخانه منابع (`#library`):** فهرست یکپارچهٔ تمام فایل‌های PDF و آرشیوهای پیوست‌شده در پست‌های منتشرشده.
- **سوالات متداول (`#faq`):** پاسخ به پرسش‌های رایج دربارهٔ نحوه انتشار مطلب، فرمت ویدیوها و سطوح دسترسی.
- **درخواست اکانت نویسنده (`#request`):** فرم ثبت‌نام برای متقاضیان نویسندگی جهت بررسی و تأیید توسط مدیر.
- **فرم تماس و بازخورد (`#contact`):** ارسال سوال، پیشنهاد یا پیام مستقیم برای مدیریت.

### ۲. صفحه اختصاصی هر درس (`course.html`)
- بارگذاری داینامیک اطلاعات درس از طریق پارامتر `id` در URL (`course.html?id=anatomy`).
- نمایش سطح درس، سرفصل‌ها، اهداف یادگیری و فهرست تمام پست‌های منتشرشدهٔ مرتبط با همان درس.

### ۳. صفحه مطالعه پست (`post.html`)
- رندر کامل محتوای بلوکی پست شامل متن، تیترها، گالری تصویر، نقل‌قول و لیست‌ها.
- **پخش‌کننده ویدیو:** پشتیبانی از لینک‌های YouTube، Aparat، لینک مستقیم و فایل‌های MP4 آپلودشده.
- **پیش‌نمایش داخلی PDF:** باز کردن جزوه‌های PDF در پنل کناری صفحه بدون نیاز به خروج از مطلب.
- نمایش مشخصات و آواتار نویسنده، زمان تقریبی مطالعه و مطالب مرتبط در انتهای صفحه.

### ۴. پنل مدیریت و نویسندگان (`panel/`)
- **کنترل دسترسی مبتنی بر نقش:** تفکیک کامل دسترسی‌های مدیر (`admin`) و نویسنده (`author`).
- **ویرایشگر بلوکی محتوا (`panel/post-editor.js`):** ساخت و ویرایش پست با بلوک‌های متن، عنوان (H2/H3)، تصویر، ویدیو، فایل (PDF/ZIP)، نقل‌قول، لیست و جداکننده با قابلیت جابه‌جایی ترتیب بلوک‌ها.
- **گردش کار انتشار (Workflow):** وضعیت‌های `draft` (پیش‌نویس)، `pending` (در انتظار تأیید مدیر)، `published` (منتشرشده) و `rejected` (ردشده همراه با ثبت دلیل برای نویسنده).
- **مدیریت کاربران و درخواست‌ها:** تأیید یا رد درخواست‌های اکانت نویسنده، مدیریت پیام‌های بخش تماس، بررسی درخواست‌های بازیابی رمز عبور و ارسال اعلان برای نویسندگان.
- **تنظیمات سایت:** ویرایش نام سایت، متون بخش Hero، رنگ اصلی قالب، آمار صفحه اصلی، ایمیل تماس و عبارت فوتر مستقیماً از داخل داشبورد.
- **پروفایل شخصی:** امکان آپلود و تغییر عکس پروفایل برای مدیر و نویسندگان.

## معماری و لایه‌های امنیتی

پروژه از دو حالت ذخیره‌سازی پشتیبانی می‌کند که از طریق فایل `js/config.js` قابل تنظیم است:

1. **حالت محلی مرورگر (`local`):** داده‌های متنی در `localStorage` و فایل‌های رسانه‌ای (تصویر، ویدیو و PDF تا سقف ۲۵ مگابایت) در `IndexedDB` (`js/media-store.js`) ذخیره می‌شوند.
2. **حالت سرور (`remote`):** ارتباط کلاینت با API مبتنی بر Node.js و Express در پوشه `server/` و ذخیره‌سازی در PostgreSQL.

### تدابیر امنیتی پیاده‌سازی‌شده در بک‌اند (`server/`)
- **احراز هویت و نشست‌ها:** استفاده از `JWT` داخل کوکی `HttpOnly`، هش کردن رمزها با `bcryptjs` و مدیریت نشست‌ها در جدول `sessions`.
- **حفاظت در برابر CSRF:** بررسی توکن CSRF برای درخواست‌های تغییر وضعیت (`POST`, `PATCH`, `DELETE`).
- **جلوگیری از حملات Brute Force:** محدودسازی نرخ درخواست (`rate-limiter.js`) و قفل موقت حساب پس از ۵ تلاش ناموفق (`account-lockout.js`).
- **سخت‌گیری رمز عبور و 2FA:** اعتبارسنجی قدرت رمز عبور (`password-validator.js`) و پیاده‌سازی احراز هویت دومرحله‌ای `TOTP` با تولید QR Code (`totp.js`).
- **ثبت رویدادها و سطح دسترسی دیتابیس:** ثبت لاگ ورود/خروج و تغییرات حساس (`audit.js`) به همراه فعال‌سازی **Row-Level Security (RLS)** روی جدول `posts` در PostgreSQL.

## راه‌اندازی و اجرا

### پیش‌نیازها
- مرورگر مدرن برای اجرای بخش فرانت‌اند
- **Node.js (نسخه LTS)** و **PostgreSQL** (در صورت اجرای نسخه سرور)

### ۱. دریافت پروژه

```bash
git clone https://github.com/Reza-Mokhtari-Hub/dentalfy.git
cd dentalfy
```

### ۲. اجرای بخش فرانت‌اند
برای اجرای محلی کافی است یک وب‌سرور ساده در ریشه پروژه بالا بیاورید:

```bash
npx serve .
```

یا صفحه `index.html` را مستقیماً روی پورت محلی خود اجرا کنید.

### ۳. راه‌اندازی سرور و دیتابیس (اختیاری / نسخه کامل)

1. وارد پوشه `server` شوید و پکیج‌ها را نصب کنید:

```bash
cd server
npm install
```

2. یک فایل `.env` در پوشه `server/` بر اساس `.env.example` بسازید و مقادیر خود را وارد کنید:

```env
DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/dental_academy
JWT_SECRET=your_long_random_secret_key
JWT_EXPIRES_IN=7d
APP_ORIGIN=http://localhost:3000
ADMIN_EMAIL=admin@rmo.local
ADMIN_PASSWORD=your_strong_password
```

3. دیتابیس `dental_academy` را در PostgreSQL ایجاد کنید و اسکیمای `server/schema.sql` را اجرا کنید (در شروع کار نیز `init.js` جداول و حساب مدیر اولیه را بررسی و همگام‌سازی می‌کند).

4. سرور را اجرا کنید:

```bash
npm start
```

5. برای اتصال فرانت‌اند به سرور، در فایل `js/config.js` مقدار `APP_CONFIG` را با آدرس سرور خود هماهنگ کنید:

```js
const APP_CONFIG = {
  storageMode: "remote",
  apiBaseUrl: "http://localhost:4000/api/v1",
};
```

## مسیرهای اصلی API

| متد | مسیر | توضیح |
| --- | --- | --- |
| `GET` | `/api/v1/auth/csrf-init` | دریافت اولیه توکن CSRF |
| `POST` | `/api/v1/auth/login` | ورود کاربر و تنظیم کوکی نشست |
| `POST` | `/api/v1/auth/logout` | خروج و پاک‌سازی نشست |
| `GET` | `/api/v1/auth/me` | دریافت اطلاعات کاربر فعلی |
| `GET` | `/api/v1/posts` | دریافت فهرست پست‌های منتشرشده |
| `GET` | `/api/v1/posts/:id` | دریافت جزئیات یک پست منتشرشده |
| `POST` | `/api/v1/author-requests` | ثبت درخواست اکانت نویسنده |
| `POST` | `/api/v1/feedback` | ثبت پیام یا سوال از فرم تماس |
| `GET` | `/api/v1/panel/posts` | فهرست پست‌ها در پنل بر اساس نقش کاربر |
| `POST` | `/api/v1/panel/posts` | ایجاد پست جدید |
| `PATCH` | `/api/v1/panel/posts/:id` | ویرایش پست |
| `DELETE` | `/api/v1/panel/posts/:id` | حذف پست |
| `GET` | `/api/v1/panel/requests` | مشاهده درخواست‌های نویسندگی (فقط مدیر) |
| `POST` | `/api/v1/panel/requests/:id/approve` | تأیید درخواست نویسنده (فقط مدیر) |
| `POST` | `/api/v1/panel/requests/:id/reject` | رد درخواست نویسنده (فقط مدیر) |
| `GET` | `/api/v1/site` | دریافت تنظیمات فعلی سایت |
| `PATCH` | `/api/v1/site` | ویرایش تنظیمات سایت (فقط مدیر) |

## ورود اولیه و تنظیمات

- مسیر ورود به پنل: `panel/index.html`
- حساب پیش‌فرض مدیر برای تست اولیه:
  - **ایمیل:** `admin@rmo.local`
  - **رمز عبور:** `rmo2026`

> **نکته:** پیش از استقرار در محیط واقعی، حتماً رمز عبور مدیر و کلید بازیابی (`recovery key`) را از داخل پنل تغییر دهید و در فایل `.env` مقادیر واقعی `JWT_SECRET` و `ADMIN_PASSWORD` را جایگزین کنید.
